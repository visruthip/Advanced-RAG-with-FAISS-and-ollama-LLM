# RAG Application – Retrieval Augmented Generation with ISO 27001 Document

---

# 1. Project Overview

## Project Title

**RAG Chat – Retrieval Augmented Generation with ISO 27001 Document**

## Objective

The objective of this project is to build an AI-powered document question-answering system using Retrieval Augmented Generation (RAG). The application allows users to ask questions about an ISO 27001 PDF document and receive contextual, accurate answers generated by a Large Language Model (LLM).

The system combines:

* Semantic search using FAISS
* Local LLM inference using Ollama
* FastAPI backend APIs
* Flask frontend interface

---

# 2. Introduction to RAG

## What is RAG?

RAG stands for:

> **Retrieval Augmented Generation**

Traditional LLMs generate responses only from pre-trained knowledge and may produce hallucinated or inaccurate answers.

RAG improves accuracy by:

1. Retrieving relevant information from documents
2. Passing that context to the LLM
3. Generating context-aware answers

# 5. Project Workflow

## End-to-End Workflow

### Step 1: User Interaction

The user enters a question in the browser UI.

Example:

```text
What are ISO 27001 access control requirements?
```

---

### Step 2: Flask Frontend

The Flask frontend:

* Captures the user query
* Sends the request to FastAPI backend
* Displays the response

---


### Step 3: FastAPI Backend

FastAPI receives the request and:

* Initializes the RAG pipeline
* Processes the question
* Retrieves contexts
* Generates answers

---

### Step 4: PDF Loading

The PDF document is loaded and text is extracted.

Handled by:

```text
rag/data_loader.py
```

---

### Step 5: Text Chunking

The extracted text is divided into overlapping chunks.

Purpose:

* Preserve semantic meaning
* Fit into embedding and LLM context windows

---

### Step 6: Embedding Generation

Each chunk is converted into vector embeddings using:

```text
sentence-transformers
```

---

### Step 7: FAISS Indexing

Embeddings are stored in FAISS for semantic similarity search.

---

### Step 8: Query Embedding

The user query is also converted into embeddings.

---

### Step 9: Similarity Search

FAISS retrieves the top-K most relevant chunks.

---

### Step 10: Context + Prompt

Retrieved chunks are combined with:

* System prompt
* User query

---

### Step 11: Ollama LLM

The final prompt is sent to Ollama for answer generation.

---

### Step 12: Response Display

Generated answer and retrieved contexts are returned to the user interface.

# 10. RAG Pipeline Deep Dive

---

# 10.1 Document Loading

PDF is loaded using PyPDF libraries.

---

# 10.2 Chunking

Large text is divided into smaller overlapping chunks.

Benefits:

* Better retrieval accuracy
* Reduced token overflow

---

# 10.3 Embedding Creation

Text chunks are converted into vectors.

Embedding captures:

* Semantic meaning
* Context relationships

---

# 10.4 FAISS Search

FAISS compares vectors using similarity metrics.

Result:

* Top relevant chunks retrieved

---

# 10.5 Prompt Engineering

Retrieved chunks are combined with:

* User query
* System instructions

---

# 10.6 Answer Generation

Ollama generates final responses based on retrieved contexts.
